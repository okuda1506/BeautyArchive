# B/ONE

[English](README.md)

## 概要

B/ONEは、美容に関する記録・予定・写真・リマインダーを一つにまとめる、パーソナル美容管理プラットフォームです。仕様は開発に伴って変わる場合があります。

## B/ONE とは

B/ONEは、美容院の施術履歴、髪型の参考写真、コスメや香水の管理、次回メンテナンスのタイミング、Google Calendar上の予定など、美容に関する情報を一つの場所に集約します。

美容に関する情報は複数のアプリやサービスに分散しがちです。B/ONEは、

**記録する → 振り返る → 次のタイミングを知る → 予約・購入する**

という一連の美容行動を自然につなげることを目指しています。

B/ONE自体が美容院予約サービスやECサイトを置き換えるのではなく、既存サービスを活用しながら、その前後にある美容体験をまとめて管理する「美容行動のハブ」として設計しています。

> **Beautyを、ひとつに。**

## 開発背景

美容に関する行動は、想像以上にさまざまなサービスや場所に分散している。

例えば美容院であれば、予約は予約サービス、予定はカレンダー、参考にしたい髪型は写真アプリ、前回の施術内容は記憶やメモに頼ることが多い。

化粧品や香水についても、購入履歴はECサイト、使用開始日は記憶、買い替え時期は感覚的に管理するなど、必要な情報が一つの場所にまとまっていない。

その結果、

- 前回いつ美容院に行ったか分からない
- 前回どのような髪型をオーダーしたか思い出せない
- 美容師に見せたい参考写真を探すのに時間がかかる
- 化粧品をいつ購入・開封したか分からない
- 買い替えや次回予約のタイミングを逃してしまう
- 美容に関する予定・記録・写真が複数のアプリに分散する

といった小さな不便が発生する。

B/ONE は、こうした美容に関する記録と次の行動を一つにまとめるために開発している。

コンセプトは、

> **美容履歴を残すアーカイブと、次の美容行動を促すリマインダーを一つにする。**

単なる美容記録アプリではなく、
```text
記録する
↓
振り返る
↓
次のタイミングを知る
↓
予約・購入する
```

という一連の美容行動を自然につなげることを目指している。

### B/ONE が目指すもの

B/ONE は、既存の美容院予約サービスやECサイトを置き換えるものではない。

予約や商品の購入そのものは既存サービスを利用しながら、その前後に発生する

- 美容履歴の記録
- 写真の保存
- オーダー内容の保存
- 次回タイミングの管理
- 美容予定の管理
- 再予約・再購入への導線

を B/ONE が担う。

つまり、B/ONE はさまざまな美容サービスをつなぐ **「美容行動の管理ハブ」** という位置づけである。

### iOSアプリとしての設計方針

現在は iOS 専用アプリとして開発している。

SwiftUI を中心に Apple プラットフォームの標準機能を積極的に利用し、iPhone に自然に馴染むシンプルで洗練された体験を目指す。

データ管理には SwiftData と CloudKit / iCloud を使用し、B/ONE 独自のアカウント登録を必要としない構成としている。

ユーザーはアプリをインストールした後、複雑なユーザー登録を行わずに利用を開始でき、対応するデータは iCloud を利用して同じ Apple Account の端末間で同期する。

Google Calendar との連携も予定しているが、Google アカウントは B/ONE へのログインには使用せず、カレンダー機能を利用するための認可としてのみ使用する。

### UI / UX の考え方

美容管理アプリである一方で、過度に装飾的なデザインにはせず、Apple純正アプリのようなシンプルで洗練されたUIを目指している。

特に、

- 写真を主役にする
- 必要な情報だけを表示する
- 入力項目を増やしすぎない
- 少ない操作で記録できる
- 次に行うべき美容行動がすぐ分かる
- AppleらしいネイティブUIを活用する
- Liquid Glass を操作UIやナビゲーションに取り入れる

ことを重視している。

美容の記録そのものを目的にするのではなく、

**「無理なく記録が続き、その記録が次の美容行動に役立つこと」**

を B/ONE の中心的な体験として設計・開発している。

## アプリの特徴

- 美容院の履歴と次回の来店準備を中心にした体験。
- これから行うこと、予定、リマインダーをすぐに確認できる画面。
- 買い替え目安は初回にユーザーが日数を指定し、以降は同じ商品の使用履歴を活用。
- ローカル保存を基本とし、対応端末間のiCloud同期を計画。

## 機能

初期リリースでは、次の機能を予定しています。

- 施術内容・担当者・写真・メモを含む美容院の履歴と、美容師に見せる参考写真・オーダー画面。
- カット・カラーなど施術ごとの次回目安と通知、外部予約サービスへの導線。
- 化粧品・香水の購入単位での記録、使用履歴、買い替え通知、再購入リンク。
- 美容予定を管理するアプリ内の月間カレンダーと、任意のGoogle Calendar連携。
- 記録と写真の書き出し。

**現在利用できる機能：** 美容院の来店記録と写真、髪型の参考写真と美容師に見せる画面、施術ごとの次回目安・通知の1週間延期・今回の目安日の変更、アプリ内の美容予定と月間カレンダー、化粧品・香水の商品画像・購入単位の使用履歴・買い替え目安とローカル通知・再購入リンク。Homeには美容院と商品の次の行動をまとめて表示します。Settingsでは通知設定、記録と保存済み写真のJSON書き出し、任意のGoogleカレンダーアカウント認可を利用できます。連携後はGoogleの予定を月間カレンダーで読み取り専用表示します。Googleの実アカウントでの認可・予定取得は未検証です。

**今後実装する機能：** B/ONEの美容予定のGoogleカレンダーへの反映。iCloud同期の設定は追加済みですが、複数端末での実動作は未検証です。メーカー表示の期限や開封後の使用期限の管理は初期リリースに含めません。

## 技術スタック

- **現在のプロジェクト:** Swift、SwiftUI、SwiftData、CloudKit、PhotosPicker、UserNotifications、Google OAuth、Google Calendar API、Xcode、XCTestのテストターゲット。

初期リリースは専用バックエンドを持たないローカルファースト構成を想定しています。

## ローカル環境構築

1. macOSにXcodeをインストールし、iOS 26.5以降のシミュレータを利用できるようにします。現時点のXcodeプロジェクトのデプロイメントターゲットはiOS 26.5です。
2. リポジトリをクローンします: `git clone https://github.com/okuda1506/BeautyArchive.git`。
3. Xcodeで`BeautyArchive.xcodeproj`を開きます。
4. `BeautyArchive`スキームと利用可能なシミュレータを選択して実行します。

記録は端末内に保存されます。Googleカレンダーの認可は任意です。iOS用OAuthクライアントIDとcallback URL schemeはプロジェクトに設定済みなので、ビルドに追加の認証情報は不要です。Google認可の動作確認には、OAuth同意画面で許可されたGoogleアカウントと、プロジェクトで有効化されたGoogle Calendar APIが必要です。
