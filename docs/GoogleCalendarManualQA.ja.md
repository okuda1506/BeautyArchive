# Google Calendar 実機確認手順

この手順は、B/ONEのGoogle連携を**実Googleアカウントで未検証**の状態から確認するためのものです。モック検証やビルドの成功は、実際の認可・同期成功を意味しません。結果を記録してから初期リリースを判断します。

## 事前準備

1. Google Cloud Consoleで、B/ONEに設定したiOS OAuthクライアントと同じプロジェクトを選び、**Google Calendar API**が有効であることを確認します。
2. **Google Auth Platform > Branding / Audience / Data Access**で同意画面を確認します。外部向けのTesting状態なら、試すGoogleアカウントをTest usersに追加します。アプリが要求するCalendarスコープは`https://www.googleapis.com/auth/calendar.events`です。[Googleの同意画面設定手順](https://developers.google.com/workspace/guides/configure-oauth-consent)を参照してください。
3. iOSクライアントのBundle IDがXcodeプロジェクトの`com.takuyaokuda.BeautyArchive`と一致し、[BeautyArchive-Info.plist](../BeautyArchive-Info.plist)のClient IDとcallback URL schemeがそのクライアントのものか確認します。Client Secretをアプリへ追加する必要はありません。
4. iOS 26.5以降のiPhoneに最新のB/ONEを入れます。Googleの**メインカレンダー（primary）**に検証用の予定を作るため、個人の通常予定と区別できるテスト名を使います。可能なら専用のGoogleテストアカウントを使います。

GoogleのTesting状態では、テストユーザーによる認可が7日後に期限切れになる場合があります。後日トークン更新が失敗したら、まず[AudienceのTesting状態](https://support.google.com/cloud/answer/15549945)を確認してください。

## 確認する操作

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 1 | B/ONEの設定で「Googleカレンダーと連携」を選び、テストアカウントで許可する | アプリへ戻り、「連携済み」と対象メールアドレスが表示される。連携しなくても既存の美容予定を使える |
| 2 | Googleのメインカレンダーで、今月の日付に`BONE-QA-外部`の予定を作り、B/ONEの予定画面を開く | その日にGoogleの予定マークと`Googleカレンダー · 表示のみ`の行が現れる。B/ONE内から編集・削除できない |
| 3 | B/ONEで`BONE-QA-美容予定`を作り、「Googleカレンダーへ反映」をオンにする | アプリ内に保存され、Googleのメインカレンダーには対応イベントが**1件だけ**作られる。アプリ内ではGoogle側の写しが二重表示されない |
| 4 | B/ONE側でこの美容予定の日時・名前を変更する | Google側の同じイベントが更新され、重複する別イベントは増えない |
| 5 | B/ONE側で状態を「キャンセル済み」にして保存する | アプリ内の予定は残り、対応するGoogleイベントは削除される。外部予約サービスの予約自体は変更されない |
| 6 | 別の連携対象予定を作り、予定一覧からそのアプリ内予定を削除する | アプリ内予定が消え、対応するGoogleイベントも削除される。削除に失敗した場合は予定画面に状態と再試行が残る |
| 7 | 連携したままネットワークを切り、別の連携対象予定を保存する。通信可能になってから予定画面で「再試行」を選ぶ | オフラインでもアプリ内予定は残り、失敗状態が分かる。再試行後にGoogleへ1件だけ反映される |
| 8 | #7で失敗状態のままアプリを終了し、再起動する | 失敗状態とアプリ内予定が残る。送信失敗状態の操作は勝手に成功扱いにならず、予定画面から再試行できる |
| 9 | 2つのテストアカウントが使える場合、Aに紐づけた予定を残して連携解除し、Bへ連携してからその予定を編集する | Aの予定がBのカレンダーに作成・変更されない。元のアカウントに再接続する案内が出る |
| 10 | Google連携を解除する | B/ONEの美容予定・記録は残り、Google予定の表示は止まる |

Google側でB/ONE由来イベントを直接変更しても、B/ONEの元の予定には取り込みません。送信待ちの処理はアプリの起動・復帰でも再開しますが、失敗として保存された操作は予定画面から手動で再試行します。
