# 起動モーションの確認手順

アプリが終了している時は中央のアプリアイコンを表示します。SwiftUI画面が表示されてから1.7秒静止し、約0.32秒でアイコンを拡大・フェードして背後の画面を見せます。通常はホーム画面で、初回利用の場合は既存の「はじめる」案内を表示します。背後の画面とデータは静止表示と並行して準備します。

iOS標準のLaunch Screenにも同じ96ptのアイコンとLight/Dark用の背景色を使用します。標準画面の表示時間はOSが管理するため、1.7秒はアプリ側の表示時間です。[AppleのLaunch Screen仕様](https://developer.apple.com/documentation/xcode/specifying-your-apps-launch-screen)に従い、標準画面には静的なUIKitの画像と背景のみを配置しています。

## 確認項目

1. 「視差効果を減らす」がオフであることを確認し、最新mainをSweetPad/XcodeからRunする。アプリスイッチャーでアプリを終了し、アイコンから起動する。アイコンだけを中央に表示し、1.7秒の静止後に素早く拡大してホームが見えることを確認する。拡大開始時にはアイコンが消えず、サイズが大きくなってからフェードする。
2. 起動済みのアプリをホーム画面へ戻してから開き直し、起動演出の待ち時間が入らないことを確認する。
3. 1.7秒の静止中や拡大中にアプリをバックグラウンドへ移し、戻った時に演出が再開しないことを確認する。
   起動時の一時的な非アクティブ状態では演出を破棄しない。コントロールセンターなどでは演出時間が進み、アプリをバックグラウンドへ移した時は演出を終了する。
4. 終了状態でApple Watchの通知から「明日また通知」を操作し、その後iPhoneでB/ONEを開く。通知処理が動き、起動演出で待たされないことを確認する。
5. Light/Dark、iPhoneの縦・横向き、iPadでアイコンの位置・サイズが静的Launch Screenからずれないことを確認する。
6. 設定の「アクセシビリティ → 動作 → 視差効果を減らす」を有効にする。アイコンは1.7秒表示し、拡大せず短いフェードで切り替わることを確認する。VoiceOverでも起動中に背後のボタンを操作できないことを確認する。
7. 初回利用では演出後に案内画面へ進み、「はじめる」でホームに進めることを確認する。

## 検証状況

`bash scripts/check-launch-presentation.sh`では、終了状態からの起動・通常の復帰・バックグラウンド起動・途中離脱・新しいプロセスの状態管理をmacOS上で検証します。静止・拡大の途中で表示が消えないこと、キャンセル、Reduce Motionの短いフェードも、制御可能な待機処理を使って確認します。シミュレータは起動しません。

2026-09-29に、起動済みのiPhone 17 / iOS 26.5シミュレータ1台で通常起動を録画し、アイコンの静止表示から拡大・フェードしてホームへ切り替わる描画を確認しました。Reduce Motionはオフです。同じアプリプロセスをバックグラウンドから戻した時は、アイコン表示と待ち時間を入れずホームへ戻ることも録画で確認しました。

通常起動の`didFinishLaunchingWithOptions`でも`applicationState`が`.background`になることを診断ログで確認しました。その値では演出を消費せず、アクティブ化を待って開始します。開始前のSceneのbackground状態も無視し、再生開始後の実際のbackground移行とWatch通知アクションで演出を終了します。

実機での描画、Light/Dark両方・全画面サイズ、標準画面のキャッシュとの切り替わり、初回利用の案内、Reduce Motion有効時の描画、VoiceOver、Watch通知のバックグラウンド起動は未検証です。Unit Test・UI TestはCPU負荷を避けるため実行していません。

アイコンを変更した場合は、`swift scripts/export-launch-icon.swift BeautyArchive/Assets.xcassets/AppIcon.appiconset/AppIcon.png BeautyArchive/Assets.xcassets/LaunchIcon.imageset/LaunchIcon.pdf`で起動用の画像も更新できます。既存の画像を96ptの角丸PDFとして配置し、標準画面とSwiftUIの両方で使用します。
