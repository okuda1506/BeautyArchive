# Apple Watch通知アクションの実機確認

## 仕組みと範囲

B/ONEがiPhoneへ予約したローカル通知を、Appleの標準機能でApple Watchへ転送します。Watch専用アプリのインストールは不要です。通知を開くと「明日また通知」「1週間後に通知」が表示され、選択した日数後の午前9時に再通知します。

Appleの[通知アクションの仕様](https://developer.apple.com/documentation/watchos-apps/adding-actions-to-notifications-on-watchos)に従い、アクションはバックグラウンドでペアリング先のiPhoneが処理します。iPhoneとWatchの接続・通知転送はOSが管理するため、iPhoneと接続できない状態で即時に反映されることは保証しません。

通知からの延期は端末内に保存されます。商品の使用日数・買い替え目安、美容院の目安日や通常の施術周期は変わりません。他のiPhone/iPadの通知へは同期しません。既存のHomeから行う美容院の延期・目安変更は、従来どおりSwiftDataの調整として扱い、その操作が通知からの延期より優先されます。

## 準備

- 最新のmainを実機iPhoneでRunし、B/ONEの通知を許可して設定でオンにする。新しい通知カテゴリへの更新のため、更新後は一度アプリを開く。
- ペアリング済みのApple Watchを装着してロックを解除し、iPhoneはロックしておく。iPhoneが使用中の場合はWatchへ転送されないことがあります。
- iPhoneのWatchアプリの「通知」で、B/ONEのiPhone通知の反映を有効にする。詳しくは[Appleの通知設定案内](https://support.apple.com/ja-jp/108369)を参照する。
- 通知タイミングを「目安日当日」にし、翌日以降に目安が来る美容院の施術と、通知をオンにした使用中の商品を用意する。通知は午前9時に届くため、実際に届く日程で確認する。

## 確認項目

1. 美容院・化粧品・香水の通知をWatchで開き、2つのアクションが表示されることを確認する。iPhoneの通知を長押しした場合も同じ操作を利用できる。
2. 「明日また通知」を選択する。iPhoneの画面を開く必要がなく、翌日の午前9時に同じ対象を再通知することを確認する。
3. 再通知に「1週間後に通知」を選択し、その操作日から7日後の午前9時へ変更されることを確認する。通知が重複しないことも確認する。
4. 延期後にB/ONEを終了・再起動し、通知設定の「何日前」を変更しても延期した通知が元の日時に戻らないことを確認する。
5. 商品を使い切り／使用終了にする、商品・購入単位を削除する、商品ごとの通知をオフにする、アプリの通知をオフにする。それぞれで延期通知が残らないことを確認する。
6. 美容院を予約済みにする、新しい施術記録を登録する、目安日・周期を変える。それぞれで古い通知から再通知できないことを確認する。
7. Homeから美容院の「1週間後に知らせる」「今回の目安日を変更」「調整を解除」を操作した場合、その設定がWatch通知からの延期より優先されることを確認する。
8. iPhoneのアプリを開いている時にWatchから延期し、通常の通知再整理と重なっても延期日時が維持されることを確認する。
9. iPhoneのアプリが起動していない状態でも操作を確認する。通知の予約に失敗した場合は、次回アプリを開いた時にエラーを表示することを確認する。

## 検証状況

日付計算、端末内保存、対象の無効化、通知リクエストのカテゴリ・メタデータ、失敗時の復元、処理の直列化は、`bash scripts/check-reminder-notification-actions.sh`のmacOS上の軽量検証で確認する。この検証は通知センターへの配信・Watchへの転送を行わず、実機確認を置き換えるものではない。

Apple Watch/iPhoneでの実配信、接続がない時の挙動、実際のバックグラウンド起動は未検証。
