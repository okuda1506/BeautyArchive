# iCloud・端末間同期の実機確認手順

B/ONEのSwiftData / CloudKit同期は、**複数端末での実動作をまだ確認していません**。ビルド成功や設定画面の「iCloudを利用できます」は、別の端末へ同期されたことを示しません。初期リリース前に、以下の操作と結果を記録します。

## 事前準備

1. 同じApple AccountでiCloudを利用できる2台のテスト用iPhoneを用意します。両方に同じコミットのB/ONEをインストールし、同じCloudKit環境を使うビルドで確認します。
2. B/ONEの設定で両端末のiCloud利用可否を確認します。Googleカレンダー連携や通知許可は、このテストの前提にしません。
3. テスト用の記録名に`BONE-QA`を付けます。既存の個人データを削除・変更しないでください。
4. 同期には時間がかかる場合があります。各操作の時刻、相手端末に反映された時刻、両端末の画面を記録します。一定時間待っても反映されない場合は、成功扱いにせず症状を記録します。

## 確認する操作

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 1 | 端末Aで`BONE-QA-カット`の来店記録を作り、施術・周期・写真2枚・オーダーメモを保存する | 端末Aで直ちに記録を開ける。端末Bでも記録、施術、2枚の写真、メモ、次回目安を確認できる |
| 2 | 端末Aで`BONE-QA-参考`の髪型参考と写真を保存する | 端末Bの参考スタイルと美容師に見せる画面で同じ写真・メモを確認できる |
| 3 | 端末Aで`BONE-QA-商品`と商品画像を保存する。購入した1本を「使用中」にし、開封日と買い替え目安の日数を入力して「目安を表示」をオンにする | 端末Bに商品、画像、1本の履歴、買い替え目安が現れる |
| 4 | 端末Aで`BONE-QA-予定`の美容予定をGoogle反映をオフにして保存する | 端末Bの月間カレンダーで予定と対象施術を確認できる。Google認可は不要 |
| 5 | 端末Bで#1のメモと#3の商品のメモを編集する | 端末Aにも編集内容が反映され、写真や履歴は欠けない |
| 6 | 端末Aをオフラインにしてテスト用の来店記録を追加し、オンラインへ戻す | オフライン中も端末Aで記録を使える。復帰後、端末Bに同じ記録が現れる。重複がない |
| 7 | 端末Bで#4の予定を日時変更してからキャンセルし、端末Aを確認する | 端末Aでも変更日時とキャンセル状態が分かる。外部予約サービスの予約は変更されない |
| 8 | 端末Bで#2のテスト用参考スタイルを削除する | 端末Aでも該当する参考スタイルと写真が消える。他の記録・写真は残る |
| 9 | iCloudを使えないテスト端末がある場合、その端末で来店記録を作る | 端末内で保存・表示でき、設定では同期できない状態が分かる。別端末へ同期済みとは表示しない |
| 10 | 端末Aで通知タイミングを「3日前」に変更し、端末Bの設定を開く。続けて端末Bで「日数を指定」を選び、日数を変更する | タイミングと日数が相手端末へ反映される。一方、各端末の通知許可と通知オン・オフは相手端末の操作では変わらない |

同時編集の優先順位はまだ実機で決めていません。余裕があれば、両端末をオフラインにして同じ**テスト用**メモを別々に編集し、再接続後にどちらの内容が残るか、重複や消失がないかを追加記録します。結果を確認せず、競合解決済みとは扱いません。

## 端末ごとの設定と残る確認事項

- 通知許可と端末全体の通知オン/オフ、OSに登録される通知は端末ごとです。通知タイミングの選択値はiCloudのKey-value storageで引き継ぐ構成ですが、[Issue #108](https://github.com/okuda1506/BeautyArchive/issues/108)の実機確認はまだ終わっていません。
- Googleの認証情報は各端末のKeychainに保存されます。美容予定が端末Bへ現れても、端末BでGoogle認可済みになったことは意味しません。Googleへの反映は別途[Google Calendar実機確認手順](GoogleCalendarManualQA.ja.md)で確認します。
- 設定画面で分かるのはiCloudアカウントの利用可否です。個々の記録がアップロード・ダウンロード完了したか、同期失敗から復旧したかは、この手順の画面確認で判定します。
